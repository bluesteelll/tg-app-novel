# tg-app-novel

> A visual novel shipped as a Telegram Mini App and monetized with Telegram Stars: a small load budget, correct
> payments, and paid content that never leaks.

The client is Svelte 5 with PixiJS v8 and the inkjs runtime ([client/](client/)); the stories are ink sources
([story/](story/)); the server is Rust (axum 0.8) on PostgreSQL 18 ([server/](server/)). The project rules, the stack
and the gate commands are in [CLAUDE.md](CLAUDE.md); how the parts fit is [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## What the app does

A player opens the bot's Mini App and lands on Home. Each story's first chapter is free; a later chapter is bought for
Stars, and the server unlocks it only after Telegram's `successful_payment` reaches its webhook. Saves live on the
server per story and slot, with the device as a cache. Chapters can hold puzzles and explorable rooms; hint texts come
from the server.

Around the stories ([docs/META-PLAN.md](docs/META-PLAN.md), all merged): a completion card at a declared ending with
the endings and achievements found; friends by invite link, a friend's profile shown only with that friend's consent;
sharing a story through a prepared message or a share link; a wallet of hints bought as packs, spent on puzzles, sent
to friends as gifts, and granted by the referral bonus; and a public privacy policy at `/api/privacy`. Where each
feature lives: [docs/FEATURE_MAP.md](docs/FEATURE_MAP.md).

### Home and the demo stories

Home ([client/src/ui/App.svelte](client/src/ui/App.svelte)) shows a tap-to-start screen and one card per story, with
Start or Continue, plus the completion card, Friends and Wallet. The tree ships two placeholder demo stories
([story/stories.json](story/stories.json), [story/chapters.json](story/chapters.json)):

| Story | Chapters | Endings |
|---|---|---|
| `manor`, "Elm Manor" | `ch1` free, `ch2` paid (`chapter:ch2`); both with rooms to explore and puzzles ([story/ch1/world.json](story/ch1/world.json), [story/ch2/world.json](story/ch2/world.json)) | `truth`, `ashes` (both in `ch2`) |
| `tide`, "The Lighthouse Above the Tide" | `ch3` free, `ch4` paid (`chapter:ch4`) | `drowned` (in `ch3`), `dawn` |

The titles are the English locale ([story/locales/en/story.json](story/locales/en/story.json)); Russian is the primary
language. The art in the tree is generated by the asset tool as placeholders ([assets/catalog.json](assets/catalog.json)); the real art is the owner's (OPEN-QUESTIONS Q2).

## Run it locally

No bot and no tunnel: the client runs in a browser against `server-dev` and a mock Telegram environment.

```powershell
npm --prefix client ci
npm --prefix client run story
npm --prefix client run assets
cargo run -p server-dev --locked
```

Then, in a second terminal, `npm --prefix client run dev`, and open `/dev/launch` on the URL Vite prints. PostgreSQL 18
binaries must be on `PATH` or in `PG_BIN`. Details, ports and troubleshooting:
[docs/runbooks/local-dev.md](docs/runbooks/local-dev.md).

## Connect a real bot

The owner's steps (PROTOTYPE-PLAN D2), each detailed in a runbook:

1. Create a bot in Telegram's test environment; Stars payments are tested there for free
   ([bot-setup.md](docs/runbooks/bot-setup.md#preconditions)).
2. Set `BOT_TOKEN`, `WEBHOOK_SECRET`, `TOKEN_KEY`, `PUBLIC_APP_URL` and `ADMIN_TELEGRAM_IDS`, plus `TELEGRAM_ENV`,
   `DATABASE_URL` and `CONTENT_DIR` (the full table: [bot-setup.md](docs/runbooks/bot-setup.md#steps), step 4; the names
   are parsed in [server/src/config.rs](server/src/config.rs)). Placeholders only in any file you commit.
3. Build the client and the paid content: `npm --prefix client run build`.
4. Run `server serve` with `STATIC_DIR=client/dist` ([deploy.md](docs/runbooks/deploy.md#steps)).
5. Expose HTTPS: a Cloudflare named tunnel, or a quick tunnel, whose URL changes on every run and is registered again
   each time ([webhook.md](docs/runbooks/webhook.md#exposing-https)).
6. In @BotFather, set the Main Mini App to `<PUBLIC_APP_URL>` (the menu button is set by the next step), and the privacy
   policy URL to `<PUBLIC_APP_URL>api/privacy` ([bot-setup.md](docs/runbooks/bot-setup.md#steps), steps 2-3).
7. Run `server setup`: the webhook with its secret, the command menus and the menu button
   ([webhook.md](docs/runbooks/webhook.md#registering)).
8. Turn on 2-step verification on the owner's Telegram account.

For production, also: replace the draft `/terms`, `/support` and `/paysupport` texts, and set `PRIVACY_OPERATOR_FILE`
to the host file with the operator's identity ([privacy-ops.md](docs/runbooks/privacy-ops.md)); a production start
refuses until both are done.
