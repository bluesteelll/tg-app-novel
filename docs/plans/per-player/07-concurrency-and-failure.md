## 7. Concurrency and failure model

| Case | Outcome |
|---|---|
| double tap on Try | the session is single-flight (`session.ts:212-214`); a second device's attempt serializes on the progress row lock; each is compared against the current run |
| two devices, one restarts | the other's next attempt is 409 `value_changed` with the current value (not counted); its store learns it and reconciles; `activated` and the next load refetch too |
| two devices, one spends the run | the other's next attempt on that run is 409 `value_changed` (spent), never `correct: false`; its world holds no outcome, so it restarts and shows the new value (§3.6) |
| reload mid-chapter | the store refetches at load; values are never saved; masks until the response |
| token expiry mid-session | http.ts's single re-auth for every new route; a failed re-auth is a failed fetch: R7's `failed` for entries with no live value, nothing for codes already shown (round 7) |
| `deactivated` during a label crossfade | the batch timeline pauses with the rest (`pauseAll`); `activated` refreshes values in the background (every shown code stays, §5.2 "Refresh") and checks the context |
| the `activated` refresh fails (round 7, r6 W1: the first request after an iOS resume, on a socket dropped in the background, CLAIM; `api/http.ts` retries only a 401) | every code already shown stays on every surface; no mask, no prompt, no frame change, no cue; an entry that held no value stays `failed` with its prompt; a code the server moved past meanwhile is harmless (a Try against it is a 409 carrying the new value, never counted) and heals at the next body (`values: a failed activated refresh keeps the shown code`, `yields: a failed activated refresh leaves an idle frame idle`) |
| two values bodies land out of order (a refresh read before a restart committed lands after the restart's 200; round 7, r6 m5) | the merge: a lower run never replaces a higher one; within a run `spent` only turns true and attempts left only fall, so the later-arriving older body changes nothing: no `V' -> V` motion, no `renewed` backwards, no second toast (`values: a late response never rolls the run back`) |
| this device's own final answer, then a values body before the world records `failed` (the close-up fade; round 7, found while resolving) | `endedHere` keeps `reconcile` from restarting it; the world records `failed` and the failed-world rule holds from then; a later restore of an older save clears the mark and restarts (`values: the own final answer never restarts before the world records it`) |
| a spent run meets a world holding `solved` or `abandoned` (a slot loaded after a replay elsewhere failed; another device's failure seen at a refresh; round 8, r7 W1) | no restart is owed: the entry stays `ready` with that run's value (the solved code, in a solved world), no mask, no prompt; Retry has nothing to do. If the story re-enters the linear puzzle, `openPuzzle` owes the restart, the frame waits `checking`, then `renewed` with the new run; a lock puzzle never re-opens (`values: a spent run in a solved world keeps its code and shows no prompt`, `yields: a linear re-entry after give-up restarts a spent run before Try opens`) |
| a Try while the store knows its code is dead: `superseded`, `restarting`, a failed restart, a restart whose 200 was lost (round 8, r7 W2) | the attempt carries the newest known run, so the server answers 409 with the current value, nothing compared or counted; the store heals and the frame plays `renewed` (or waits for the restart). Never a `wrong` against a value this device did not show (`puzzles: a try while superseded sends the last known run`) |
| a Try before any values body (the first fetch failed) | no run is sent; the server answers 409 with the value (§3.5 step 4), so the Try loads the code: `checking`, `renewed`, the prompt leaves; nothing counted (`yields: a try with no known run unmasks the code instead of judging it`, `attempt_without_run_409_not_compared`) |
| two refetches of one puzzle overlap (two statuses naming newer runs, a Retry over an `activated` refresh; round 8, r7 m5) | each request has a token; p awaits the newest; the older one's failure changes nothing, its success merges; only the awaited request's failure shows the prompt (`values: an older refetch's failure leaves the newer one's entry pending`) |
| a restart keeps failing across resumes (round 8, r7 m4) | each successful automatic body re-posts it but keeps `fail`: the spans stay masked and the prompt stays up with no slide out and back; the re-post's 200 clears both; Retry or a Try's 409 re-posts with `fail` cleared (the user's action) (`values: an automatic re-post of a failed restart keeps the prompt`) |
| the next chapter is entered with a spent puzzle in the chapter left (round 8, r7 m3) | `chapterChanged` reconciles nothing; `chapterEntered` starts a new store generation, whose first body reconciles against the new chapter's world; the chapter left is untouched on the server (`yields: a chapter change restarts nothing of the chapter left`) |
| the paywall resume of another chapter's start (`game.ts:886-907`; found while resolving r7 m3) | `chapterLeft()` installs the empty world in place of that `restore` and `sync`s the store with no wanted chapter, which drops it, so no puzzle of the chapter left is restarted (`game: a paywall resume of another chapter restarts nothing of the chapter left`) |
| after that paywall, a slot of the chapter left is loaded (Menu -> Saves, `game.ts:1532-1549`; "load theirs"; `resumeBody` reuses `s.ch` and skips `enterChapter`, `:887`; round 9, r8 W1) | the `restore` `sync`s a store that holds no generation of the chapter, so it loads the chapter's values: the spans mask with their shimmer for one request, then show the codes; a failure is the first fetch's (prompt + Retry); the first body reconciles against the restored world (`game: a resume of the chapter left at a paywall loads its values again`) |
| a language switch in a chapter with shown codes (K49: Settings -> English in a free chapter loaded in Russian; `setLang` replaces `s.ch` with `{ ...ch, en }` and installs no world, `game.ts:1946-1959`, `chapters.ts:273`; round 10, r9 W1) | the store is keyed by the `ChapterId`, which the new object keeps: every code stays shown on every surface (the diary, the line, the backlog), no request, no mask, no prompt; the line on screen re-reveals in English as K49 does today (`game: a language switch keeps the shown codes`, `values: a new object of the held chapter keeps every code`) |
| any path that still meets a per-player puzzle the store does not hold (a defect class, RULINGS 135 (a); unreachable on main by §5.2's audit, round 10) | never a wait: `failed` (`unheld`), the mask with its shimmer, Retry by `syncPrompt`, which the first `render` of the mask schedules when no store event or installation did (round 10), a frame `idle` + `puzzle:ready` with Try enabled; Retry, a Try's 409, `activated` or a status load the chapter (`values: every masking state has an action that resolves it`, `yields: a frame over a puzzle the store does not hold shows the failing state with Retry`, `yields: a render that meets a puzzle the store does not hold shows the Retry prompt`) |
| a Try's 409 settles a superseded entry, then the refetch it awaited fails (round 9, r8 m4) | the settling body cleared `awaiting`, so the failure fails nothing: V' stays shown, no prompt (`values: a 409 that settles a superseded entry survives its refetch's failure`) |
| a store change while an attempt is in flight (round 8, r7 m1) | `Open.trying` (set by `post(o)`, cleared by that attempt's pass) holds `syncValues`; the store's change inside the session's `#settle` never cues before the outcome; a `busy` reply runs no pass (E-P17 (b)) |
| a 429 countdown runs while the store changes (round 7, r6 m3) | the frame keeps `rate-limited` and its seconds; at the zero one pass writes `idle` with the store's patch and plays one cue (`ready`, or `renewed` for a run change); the clue spans change at once with their own motion (`yields: a store change during a countdown waits for its zero`) |
| the values stay failed for minutes (no network) with a masked label on the art | the shimmer draws at the ambient cap (20 / 30 fps) while no batch runs, holds after `IDLE_AFTER_MS` with no input (the loop's idle), draws nothing while paused or covered; Retry or the next response unmasks it, and with no masked view left the loop stops listening (r3 W3) |
| a toast dismissed while its entry motion runs, or re-shown while it leaves | the entry `Animation` is cancelled and the leave plays from the current frame; a key shown again while leaving cancels the leave and plays `in` on the same element (GM6t, `stackOf`) |
| lost WebGL context | restorable: the registry revive redraws labels; hard: `rebind` re-creates anchors, art and labels (e2e §9 GM6d2) |
| story update between sessions: text edit | no change (templates render at display) |
| story update: domain change | keep-if-fits, else a forced re-draw (run + 1); the client's old run gets 409 and refetches |
| story update: rename / move to another chapter | rows stay under the stable key (§3.8); the client save is mapped by GM2b's step 0 |
| story update: a puzzle removed | the build refuses until its key is retired by `--retire-puzzle` (`puzzle-key/dropped`); after a `release` line that is refused until OQ5's compensation step exists (m7); deleting the key's log line instead breaks the chain (`puzzle-key/chain`, W4); its rows stay |
| rollback to an earlier release, then forward again | previous binary + previous content; rows of puzzles the older content lacks wait under their keys and are served again later; nothing moves, nothing refuses a start (`rollback_then_forward_keeps_unlocks`) |
| per-player puzzle turned static / static turned per-player | static: the row is ignored, and a stale tab's `run` is ignored too, so its answer is compared as a static one (m11); per-player: issued at the next fetch; a solve stays a solve. A stale tab whose world still says static sends no run: 409 with the value, nothing compared (round 8; round 7 compared its static guess against the new per-player value and counted it); its session has no value port, so the check ends `idle` + `puzzle:ready` and the next chapter load brings the per-player world |
| a store-driven restart while a paid hint ladder is open (another device spent the run; `activated`, Retry, a forced re-draw) | the old run's tier texts are dropped at the change; the ladder re-fetches and shows the new value with `puzzle:hint-shown`; no second purchase (`AlreadyUnlocked` path untouched); Try sends the new run (W3, §3.6 race row) |
| a backlog line of an earlier chapter, or saved before a rename, opened in the current chapter | another chapter's placeholder renders `still` (never this chapter's value, no endless shimmer); a pre-rename id resolves through `renamed.puzzles` (W5, §5.2) |
| a lock tapped while the chapter's values are in flight (slow network, up to `REQUEST_TIMEOUT_MS` 20 s, `api/http.ts:51`) | the frame opens at once in the Try-pending state (`checking`, `puzzle:checking`), Try disabled, then idle with `puzzle:ready` whether the values land or fail; a failure also shows the Retry prompt and leaves the clue spans masked (W6; round 6, r5 W2: `syncValues`; round 7, r6 m4). A lock tapped while only an `activated` refresh is in flight opens idle at once (r6 W1) |
| the store changes (an `activated` refresh, a Retry, another device's run) while a Try is in flight | `syncValues` waits; the outcome's pass (`settle`) writes the outcome with the store's patch in one `setFrame`: one cue for a same-run count change (the outcome's), and `renewed` after it only when the run itself changed; compared against what the frame shows, so the attempt's own count adds no cue (round 7, r6 m1, m3) |
| response after unmount / chapter change | dropped (store generation); a restart already posted completes on the server, and the next load reads its run |
| (reconcile P1, E-P20) a lock tap while values load **and** the frame's type chunk is not in | the frame is written `busy`, `checking`, unshown; its cues are dropped; engine's load hold plays (`ui-state:waiting`, `panel: 'puzzle'`); at the chunk write the bus records `waited`, `panel-open`, `checking`, `opened`, and the breath loops until the end key (`yields: a lock tap while values load opens the frame checking`, deferred-chunk fixture); values that land before the chunk play no frame cue and the frame appears `idle` (`yields: values that land before the host chunk play no frame cue`) |
| (reconcile P3, r10 open question 1) the values prompt is up and the player exits to the story list | `Yields.dispose()` dismisses `values_failed` and sets `disposed`; a `syncPrompt` microtask queued by a render just before is a no-op; the second `dispose` of `exitNow` -> `endSession` is a no-op (`yields: dispose dismisses the values prompt and a queued prompt stays down`) |
| (reconcile P3, r10 m2) the player reads the diary in a room while a later path leaves a puzzle unheld | the document's spans render through yields' wrapper, so the mask schedules `syncPrompt` and Retry shows in the same task (`yields: a document that meets a puzzle the store does not hold shows the Retry prompt`, GM6c4) |
| (reconcile P2, shots I-9 / S14) a dissolve to another shot while a masked label shimmers on the old root | the old root's label views leave with it; their holds are released at the dissolve's swap (after the snapshot render), with the root's other `scene:*` holders; the snapshot carries the old picture; the new root's labels fade in from the swap (`executor: a dissolve releases the old root's label holds at its swap`) |
| (reconcile P2, shots I-11) a story cut back to a room shot inside an event | the batch gets the room's props **and labels** from I-11's method (R-E32), so the drawer's code is on its art again, with its own fade-in (`yields: a room's commands for a story cut carry its labels`, GM6d2; SH5a's `withRoomProps` appends them verbatim); reconcile r2 (m2): this is the story step's batch, applied by `stage()`, not through `held`; reconcile r3: R-E32 adopted, the method is `roomFor(bg)` ([engine GM3b `mech-state-visuals`](../engine/12c-lanes-gm3.md#gm3b-mech-state-visuals)), and a value that lands while the cut back loads is sent by the labels job after the step's intent (`yields: a value that lands while a story cut back to the room loads reaches its labels after it`) |
| (reconcile P2) a value change for the current room with no other visual change | a labels-only state batch through `held` with `'no-load'` (R-E33): no `ui-state` hold while `stats().stale === 0 && !stats().reviving` (RULINGS 152; reconcile r2, m1), else a hold at `centre` as every load-free batch; the changed label crossfades (`yields: a value change on the current room applies its labels with no hold`, GM6d2) |
| (reconcile r2, W2) a value change for room R during a room event that has cut to another shot (R's `on: 'bg'` code masked under the Retry toast; the player taps Retry, or an `activated` refresh lands, while CU A of the event is on stage) | yields sends nothing: the stage's bg is CU A's, not R's; the code is not drawn on the close-up. Were a stale command ever applied (any producer), the executor ignores it: its `bg` is not the root on stage (`yields: a value change during a cut-away sends no labels`, `executor: a labels command whose bg is not on stage attaches nothing`) |
| (reconcile r2, W2) a value change for room R while a CG covers R's own picture | the labels-only batch goes (R's root is still on stage under the CG); the label crossfades unseen and shows the current code when the CG leaves (`yields: a value change under a CG over the room updates its labels`) |
